# AGENTS.md

GTK4 desktop app (C++23, gtkmm-4.0) for browsing the images in a directory,
extracting sub-regions into new images, and related convenience features.
GPL-3.0-only.

## Build & run

- Compiler: **g++** (GCC >= 13; `std::format` needs 13, `std::print`/`println` need 14).
- Dependencies: prefer the **vcpkg manifest** (`vcpkg.json`) via the CMake toolchain;
  fall back to system packages (`gtkmm-4.0`, `gegl-0.4`) found by pkg-config/find_package.
- Presets live in `CMakePresets.json` (not committed yet — commands below assume them):

    cmake --preset dev                 # configure (Debug, vcpkg toolchain, compile_commands.json)
    cmake --build build -j             # build
    ctest --test-dir build --output-on-failure
    ./build/tests/imagemgr_tests "[core]"    # single test / tag

- `compile_commands.json` is generated by the dev preset; clang-tidy needs it.

## Code quality

### Naming and comments (top priority)

- Names must be fully descriptive: `cropped_image`, `source_directory_path`, `visible_region`.
  Avoid abbreviations except the universally understood (`i`, `x`, `y`, `id`). If a name
  needs a comment to explain what it holds, rename it instead.
- Every non-trivial function/method gets a comment block above it covering, as applicable:
  what it does and why it exists; when/how it should be called; preconditions; ownership
  and lifetime of returned/borrowed values; error behavior; and thread-safety.
- Comment blocks explain **intent and contracts**, not a restatement of the code.

### Ownership and lifetime (top priority)

- Prefer automatically-scoped values (stack) and value semantics. Do not heap-allocate
  unless the object must outlive the current scope, has dynamic/polymorphic lifetime, or
  the framework requires it (GTK/gtkmm widgets, GObject).
- No raw `new`/`delete` and no owning raw pointers. On the heap, use
  `std::unique_ptr`/`std::shared_ptr`; at the gtkmm boundary use `Gtk::make_managed` /
  `Glib::RefPtr`. Watch GObject floating refs — leaks come from here.
- `shared_ptr` is only for genuine shared ownership; reach for `unique_ptr` or a value
  otherwise.

### Other quality rules

- **Error handling.** Core returns `std::expected<T, Error>`; exceptions only for
  programmer/exceptional errors. Translate to/from `GError` only at the gtkmm/GIO
  boundary; never let a `GError` into core or an exception escape a GTK signal handler.
- **C++23 idiom.** Prefer `std::span`, `std::string_view`, `std::ranges`, `std::format`,
  `std::optional`, designated initializers. No C-style arrays, no `malloc`, no
  `using namespace` in headers.
- **API contracts.** `const` wherever possible; `[[nodiscard]]` on factories/lookups;
  `noexcept` on non-throwing accessors/moves.
- **Strings.** `std::string`/`std::string_view` in core; convert to `Glib::ustring` only
  at the GTK boundary. Assume UTF-8 everywhere.
- **Threading.** GTK4 is single-threaded: touch widgets only from the main loop. Decode /
  thumbnail / GEGL work runs off-thread and marshals back via `Glib::Dispatcher` or
  `g_main_context_invoke`. Top correctness trap in this codebase.
- **Logging.** GLib structured logging (`g_message`/`g_warning`/`g_debug`); never
  `std::cout`/`printf` in library or UI code.
- **Sanitizers.** An ASan+UBSan preset is used when running tests.
- **Warnings.** g++ baseline `-Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion
  -Wshadow`; `-Werror` in CI only.
- **Formatting is not a priority and is not gated.** Match surrounding style, and do not
  reformat untouched code in a change.
- **Definition of done.** Build clean -> clang-tidy on changed files -> tests green.
  Behavior changes need a `core/` test; GTK-only changes are verified manually.

## Architecture

    src/main.cpp     # Gtk::Application bootstrap only
    src/app/         # windows, actions, signal wiring (gtkmm)
    src/core/        # pure C++ image logic — must NOT include gtkmm
    src/io/          # directory scan, load/save (Gio::File), GEGL bindings
    tests/           # Catch2 v3 tests, core + io only
    resources/       # .ui / .gresource

Rule: `core/` stays headless and unit-testable. If image logic needs a widget to work,
it belongs in `app/`, not `core/`.

## Gotchas

- Use `Gio::File`/`Gio::ListStore`/`Gio::FileMonitor`, not raw POSIX paths, for I/O and
  directory watching.
- GEGL is a C library operating on `GeglBuffer`; it is independent of the GTK main loop
  and is where the actual pixel work lives.
- Gtk::Application setup must go through `Gtk::Application::create()`; do not call
  `gtk_init`.

## Testing

Catch2 v3 (`find_package(Catch2 3)` / vcpkg `catch2`). Tests target `core/` and `io/`;
no GTK-widget tests are required. Run all with `ctest`, one with
`./build/tests/imagemgr_tests "<name-or-tag>"`.
